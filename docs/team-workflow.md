# Как команда проводит Story от задачи до кода

Учебный пример для [Story #2](https://github.com/UnusualNick/sber-agile-2026/issues/2), которая является дочерней задачей [Epic #1](https://github.com/UnusualNick/sber-agile-2026/issues/1).

1. Участник выбирает Story и проверяет критерии приёмки.
2. От актуального `master` создаёт ветку `story-2-team-workflow`. Номер задачи в имени ветки позволяет быстро найти контекст изменения.
3. Ветку используют для небольшого, проверяемого изменения. В этом примере добавлен данный документ и обновлён README.
4. После коммита и `push` участник открывает Pull Request в `master`, связывая его со Story.
5. После проверки PR сливается в `master`; Story отмечается выполненной.
6. Wiki-страница содержит ссылки на Epic и Story, а также на репозиторий и итоговый PR.

Это демонстрационный рабочий процесс, а не код реального продукта. При оценке ДЗ важна прослеживаемая связь между задачей, документацией и изменением в репозитории.
